# NOpartisan 0.3.1 — local release candidate

## Proposed Mozilla release notes

- Automatically get updated political keywords after a new installation and
  every 24 hours while Firefox is running. No URL setup or manual download needed.
- Start filtering immediately using included rules, even offline. Failed updates
  keep current filters and retry later.
- Preserve existing personal keywords, custom sources, cached filters, filtering
  preferences and update opt-outs when upgrading.
- Keep permanent political vocabulary active after every download.
- Automatically filter individual X trends labeled Politics, while retaining
  unrelated Gaming and News trends. Improve local trend inspection diagnostics.
- Show clear keyword counts, update progress, last success/error and next check.

Permission change: installation now requests HTTPS access to raw.githubusercontent.com
for keyword downloads. GitHub receives ordinary connection metadata, including
IP address and the requested file address. No feed content, personal keywords,
browsing history, matched phrases or analytics are uploaded. Automatic updates
can be disabled in settings, and Firefox host access can be revoked; offline
filtering remains available.

## Fresh install versus migration

`core.defaults.autoUpdate` stays false as a deliberate legacy fallback.
`runtime.onInstalled` enables autoUpdate only for reason=install and genuinely
empty extension storage. It persists enabled filtering, empty personal keywords,
the maintained source and autoUpdate:true, then starts an update independently
of content-script initialization. Bundled and foundational loading never await
that request. A first-install status page discloses the behavior; it does not
require a configuration step.

Upgrades preserve settings verbatim. A legacy installation without settings gets
the legacy defaults (updates off); a missing autoUpdate value remains off. A
reinstalled development add-on with existing data is not mistaken for a fresh
user. Existing saved custom HTTPS raw.githubusercontent.com URLs within a
nopartisan repository remain fetchable; newly entered nondefault sources are
rejected. Newly configured sources must be the exact maintained URL.

The required update host is `https://raw.githubusercontent.com/*`, without
subdomain, arbitrary-host or HTTP wildcards. Firefox normalizes host grants at
the origin level, so a path in the manifest is not a security boundary. Default
requests use the approved full URL, omit credentials/referrers, reject redirects,
limit the body to 1 MB and validate schema 1. A successful download is merged
with the packaged foundation and cached with count/status/timestamps in one
storage.local.set operation. storage.onChanged reloads already-open content
scripts. The downloaded count excludes foundation entries added locally; the
active count is deduplicated across foundation, current list and personal terms.

Success records a due time 24 hours later. Failure records the local error and a
one-hour retry without deleting the known-good cache. Startup recreates the alarm
at the saved due time, or catches up if overdue. An opt-out clears the alarm and
prevents automatic work. Regaining update permission can retry for opted-in users.
Permission checks before fetch and before cache publication handle revoked grants.
Concurrent requests share one operation; source changes or an opt-out during an
automatic request prevent obsolete results from being published.

## Remaining release checks

The 24-hour elapsed interval is asserted from real saved timestamps/alarms and
startup recovery, not observed by leaving Firefox running a full day. Invalid,
empty and oversized downloads are unit-tested; real Firefox tests use actual
GitHub data and controlled connection failures. Actual user acceptance of the
new AMO installation prompt, Mozilla signing/delivery and the final signed
candidate remain untested until submission is authorized. Authenticated live X
and live Reddit/Facebook checks remain manual; the exact political-card manual
test is in ../alito-trend-fix.md, using build marker trend-foundation-1 and
extensionVersion 0.3.1 in the report.

Current permission/policy references were checked before implementation:
[Firefox host permissions](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/host_permissions),
[Firefox origin normalization](https://github.com/mozilla-firefox/firefox/blob/main/toolkit/components/extensions/ExtensionPermissions.sys.mjs),
[Mozilla policies](https://extensionworkshop.com/documentation/publish/add-on-policies/),
and [data-consent taxonomy](https://extensionworkshop.com/documentation/develop/firefox-builtin-data-consent/).
No new user-data payload or telemetry category was introduced; the network request
is for public filter data, and listing/settings/privacy text disclose it. Recheck
Mozilla's announced December 2026 policy revision if submitting after it takes effect.

Files changed for automatic updates: extension/background.js, core.js,
manifest.json, options.js and options.html; package.json/package-lock.json;
background/options/core and inspection test harnesses; shared Firefox test helpers
and real-network runner; README, PRIVACY and Mozilla submission/release copy.
The recent X adapter and foundation files are preserved. No OMV scheduling,
services or deployment were changed. No merge, push or Mozilla publication occurs
as part of these build/test commands.
